# 전처리 STAR 실행 기록

## S — 실제 문제

2026-09-26 첫 RBD24 실행이 `conflicting_entity_window`로 중단됐다. 16,936행 중 timestamp/user_id/entity 조합은 16,806개이며 130개 조합이 두 번씩 나타난다. 첫 충돌은 동일 라벨에서도 여러 관측 특징이 다르다. 한 행을 임의로 선택하면 왜곡된다.

## T — 개선 이유

충돌을 정상 또는 공격으로 추측하지 않고 실험 가능 범위를 명확히 제한한다. 원본의 실제 window 의미가 확인되기 전 서비스 연결을 승인하지 않는다.

## A — 수정 전 계획

완전히 같은 선택 특징·라벨 행은 중복 제거하고, 같은 entity/time에서 특징 또는 라벨이 충돌하면 해당 조합의 모든 행을 격리한다. 감사 결과에 격리 조합·행 수를 기록한다. 동일 시각은 여전히 같은 분할에만 들어간다. fixture로 양쪽 행 제거와 완전 중복 제거를 검증한 뒤 다시 실행한다.

## R — 검증 결과

아래 후속 실행 기록으로 갱신한다. 첫 실행 실패를 성공으로 집계하지 않는다.

검증 완료: 충돌 130개 조합의 260행을 모두 제외하여 16,676행을 남겼다. 실제 완전 중복 제거는 0행이었다. fixture에서 충돌 전체 제외·완전 중복 제거를 확인했으며 실제 RBD24의 네 모델 학습도 완료했다. Arrow의 sandbox CPU cache 조회 경고가 있었으나 데이터 읽기와 학습은 성공했다.

HTTP는 178,939행 모두 파싱됐다. 5분 관측 15,463개를 만들었고 capture 경계 146개와 요청 2개 미만 window 21,154개를 제외했다. 초 단위 동일 요청 2,702건은 실제 반복일 수 있어 보존했다. 부재한 session/event ID를 만들어 중복 제거하지 않았다.

RBA 완료: 첫 250,000 CSV 행을 검사해 필수 값 누락 13행과 prefix cutoff 시각 묶음 1행을 제외하고 249,986개 관측을 생성했다. candidate label0=226,558, attack-IP만 표시된 unknown=23,424, ATO label1=4다. 원본 ZIP 전체 checksum은 검증했지만 CSV 전체를 처리한 것은 아니다.
