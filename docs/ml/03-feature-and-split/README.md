# 특징과 시간순 분할

상태: 실행 전 계획 · 2026-09-26. 실제 수행 결과는 같은 디렉터리의 결과 문서로 갱신한다.

## S — 상황

랜덤 분할은 같은 시간 window와 미래 사용자 이력을 양쪽에 넣어 평가를 부풀릴 수 있다.

## T — 과제와 이유

source별 특징의 단위·결측 정책·순서를 고정하고 train/calibration/test를 시간순으로 나눈다.

## A — 실행 방법과 선택 이유

HTTP는 가명 client×UTC 5분 비중첩 window를 사용한다. 로그인은 과거 이력만 사용한다. 같은 시각 그룹을 경계에서 쪼개지 않고 window/capture 경계를 제외한다. 전처리 통계는 train만 사용한다.

## 예상 문제와 개선 계획

겹치는 window·동일 사건·미래 이력 누수 테스트를 추가한다. 학습에서 보인 주체와 신규 주체 평가를 나눈다. 관측 공백을 정상 저활동으로 단정하지 않는다.

## R — 결과

미실행. 계획을 통과 결과로 표시하지 않는다. 실행 명령·환경·입력 범위·소요 시간·검사 결과·실제로 발생한 문제와 수정 내용을 기록한다.

## RBA 구현 전 세부 결정

공식 제작자 설명을 다시 확인했다(https://github.com/das-group/rba-dataset). 합성 로그인 자료는 연구용이며 운영 IDS에 사용하지 않는다. 첫 250,000 CSV 행을 스트리밍하여 메모리·실행 시간을 제한한다. 시간순 여부를 검증하며 마지막 timestamp 묶음이 잘리면 통째로 제외한다. timestamp가 같은 행은 모두 이전 시각까지의 이력만 참조한다.

입력 country/IP/device/browser의 사용자별 과거 빈도·신규성, 과거 시도 수, 첫 관측 여부, 이전 관측 이후 시간을 사용한다. 성공 여부·RTT·공격 라벨은 특징에서 제외한다. 공격 라벨로 과거 이력 업데이트를 제한하지 않는다(온라인 시점에 알 수 없는 정답 누출 방지). 따라서 과거 공격에 의한 이력 오염 가능성은 남는다.

라벨은 ATO=true → 1, ATO=false이며 attack-IP=true → -1(불확실), 둘 다 false → 0(자료상 후보 음성)으로 정의한다. 성공/실패를 라벨로 변환하지 않는다. prefix에 ATO가 없으면 recall을 계산하지 않고 지도학습은 SKIPPED로 남긴다. 신규 사용자 평가는 시간 holdout 내 신규 사용자 부분집합이며 독립 사용자 무작위 holdout을 완료했다는 뜻은 아니다.
