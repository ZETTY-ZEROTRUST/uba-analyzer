# 자료 출처와 검증

다음 S/T/A는 2026-09-26 실행 전에 기록한 계획이다. 이후 수행 여부와 실제 문제·개선·검증은 [결과 기록](RESULTS.md)을 따른다.

## S — 상황

공개 자료 4종은 HTTP 요청·로그인·기기 행동 window로 단위가 다르며 정답 정책도 다르다. 기존 업무 코드와 사용자 실험을 보존한다.

## T — 과제와 이유

자료별 URL·라이선스·파일 크기·checksum·스키마·시간·label 의미를 기록하고 실제 확보 범위를 구분한다.

## A — 실행 방법과 선택 이유

공식 metadata를 고정하고 다운로드 크기·checksum을 검사한다. HTTP는 정답 없는 오염 가능 outlier 실험, RBD는 task별 label 0 학습/0·1 평가, RBA는 attack 표시를 제외한 학습을 계획한다. -1을 정상으로 바꾸지 않는다.

## 예상 문제와 개선 계획

다운로드 실패·checksum 불일치는 재개/재다운로드 후 검증한다. 부분 파일을 완전한 자료로 사용하지 않는다. 승인 범위는 공개 자료와 로컬 학습뿐이다.

## R — 결과

계획 작성 당시 미실행이었다. 이후 실제 실행과 미완료 범위를 [RESULTS](RESULTS.md)에 기록한다.
